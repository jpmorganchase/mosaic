# {meta.title}

There are several admin urls exposed by Mosaic that provide an insight into how the filesystem has been configured and a way to remotely manage sources.

## Endpoints

| Endpoint                       | Method | Description                                              | Params                 |
| ------------------------------ | ------ | -------------------------------------------------------- | ---------------------- |
| `/_mosaic_/config`             | GET    | Returns the JSON from the Mosaic config file             | n/a                    |
| `/_mosaic_/content/dump`       | GET    | Returns the entire mosaic filesystem as JSON             | n/a                    |
| `/_mosaic_/sources/list`       | GET    | Returns a collection of active sources                   | n/a                    |
| `/_mosaic_/source/add`         | POST   | Adds the source                                          | definition & isPreview |
| `/_mosaic_/source/stop`        | PUT    | Stops the source with the provided name                  | name                   |
| `/_mosaic_/source/restart`     | PUT    | Restarts the source with the provided name               | name                   |
| `/_mosaic_/tags/list`          | GET    | Returns the tag names known to the filesystem            | n/a                    |
| `/_mosaic_/webhooks/bitbucket` | POST   | Refreshes git repo sources when Bitbucket reports a push | Bitbucket push event   |

## Authentication

Every endpoint except `/_mosaic_/tags/list` and `/_mosaic_/webhooks/bitbucket` can reveal or change
server state, so they are protected by `MOSAIC_ADMIN_SECRET` on the CLI process:

- **Secret set:** requests must send it. Opening an endpoint in a browser shows a login prompt; enter
  any username and the secret as the password. From scripts, send it as a bearer token (or in an
  `x-mosaic-admin-secret` header):

  ```
  curl -H "Authorization: Bearer $MOSAIC_ADMIN_SECRET" http://localhost:8080/_mosaic_/sources/list
  curl -u admin:$MOSAIC_ADMIN_SECRET http://localhost:8080/_mosaic_/sources/list
  ```

  Requests without a valid secret get `401`.

- **Secret not set:** the endpoints are open when `NODE_ENV=development` (the reference site's
  `yarn serve` and `yarn debug` scripts set it) and return `403` otherwise, including when
  `NODE_ENV` is unset.

Basic auth sends the secret base64-encoded, not encrypted, so only use it over HTTPS outside local
development.

## Bitbucket webhooks

`/_mosaic_/webhooks/bitbucket` receives Bitbucket Data Center push events, so git repo sources pick up
new commits within seconds instead of at their next scheduled check. Bitbucket can't send the admin
secret, so the endpoint checks the webhook's signature instead: it only exists when
`MOSAIC_BITBUCKET_WEBHOOK_SECRET` is set, and rejects requests that aren't signed with it (`401`).
See [Refresh on push](../sources/git-repo-source#refresh-on-push-bitbucket-webhooks) for the setup.

## Workflows

The editor's save workflow runs over the `/workflows` WebSocket. It uses the server's repository
credentials, so it only runs for messages that carry a `token` equal to the CLI's
`MOSAIC_WORKFLOWS_SECRET`; without that variable no workflow runs. The site sends the same value from
its own `MOSAIC_WORKFLOWS_SECRET` (see `packages/site/README.md`). The placeholder value committed in
the site's `.env.development` is ignored unless `NODE_ENV=development`.

## Browser access (CORS)

The CLI sends no CORS headers by default, so web pages on other origins can't read its responses. Set
`MOSAIC_CORS_ORIGINS` to a comma-separated list of origins to allow specific ones.

## Environment variables

`mosaic serve` checks these when it starts, before any source loads. If a value is invalid it exits
with code 1 and lists every problem as `NAME: reason`. Empty values count as unset.

| Variable                        | Values                                                            | Default                                   | Purpose                                                                                                                                    |
| ------------------------------- | ----------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `MOSAIC_ADMIN_SECRET`           | Secret, not blank                                                 | Unset: admin API open only in development | Protects the admin endpoints (see [Authentication](#authentication)).                                                                      |
| `MOSAIC_WORKFLOWS_SECRET`       | Secret, not blank                                                 | Unset: no workflow runs                   | Required in every `/workflows` message (see [Workflows](#workflows)).                                                                      |
| `MOSAIC_CORS_ORIGINS`           | Comma-separated origins, each `scheme://host[:port]` with no path | Unset: no CORS headers                    | Origins allowed to read the CLI from a browser. Write them as the browser sends them, e.g. `https://docs.example.com` (no trailing slash). |
| `MOSAIC_REVALIDATE_URL`         | http(s) URL. Needs `MOSAIC_REVALIDATE_SECRET`                     | Unset: the site is not notified           | The site's revalidate endpoint, e.g. `https://docs.example.com/api/revalidate`. The CLI calls it whenever a source updates.                |
| `MOSAIC_REVALIDATE_SECRET`      | Secret, not blank                                                 | –                                         | Sent to `MOSAIC_REVALIDATE_URL`; the same value as the site's `MOSAIC_REVALIDATE_SECRET`.                                                  |
| `MOSAIC_SOURCE_BOOT_TIMEOUT_MS` | Whole number of milliseconds up to 2147483647; `0` waits forever  | `60000`                                   | How long a source may take to start before `mosaic serve` gives up on it.                                                                  |
| `BITBUCKET_API_URL`             | http(s) URL                                                       | –                                         | Bitbucket REST API used by the Bitbucket save workflow, e.g. `https://bitbucket.example.com/rest/api/1.0`.                                 |
| `NODE_ENV`                      | `development` or anything else                                    | Unset                                     | `development` opens the admin API without a secret and accepts the placeholder `MOSAIC_WORKFLOWS_SECRET`. Not validated.                   |

The placeholder `MOSAIC_WORKFLOWS_SECRET` committed in the site's `.env.development` is not an error;
outside development it simply counts as unset. `mosaic upload` reads `MOSAIC_S3_BUCKET`,
`MOSAIC_S3_REGION`, `MOSAIC_S3_ACCESS_KEY_ID` and `MOSAIC_S3_SECRET_ACCESS_KEY` and stops if any is
missing. For the site's variables, see the
[site README](https://github.com/jpmorganchase/mosaic/blob/main/packages/site/README.md#environment-variables).
